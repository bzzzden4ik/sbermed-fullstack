4. NEW BACKEND DOMAIN: PATIENT CASE
==================================================

IMPORTANT: the current backend has an Appointment system, but it does NOT have a system for patient complaints/cases.

You must implement this new domain.

A Patient Case is NOT the same as an Appointment.

Appointment:
Patient → Doctor → Date/Time

Patient Case:
Patient → Complaint → AI Summary → Doctor Review → Decision

A Patient Case may eventually lead to an Appointment, but creating a case must NOT automatically create an appointment.

Implement the necessary:

- database model(s)
- relationships
- schemas
- repositories/services/use cases following the existing architecture
- API endpoints
- authorization

Use the existing backend patterns instead of introducing unnecessary abstractions.

A case should contain the relevant patient, doctor, complaint, AI-generated structured summary, status, decision and timestamps. Add only fields that are actually needed.

Suggested lifecycle:

OPEN
→ AI_COLLECTING
→ READY_FOR_DOCTOR
→ UNDER_REVIEW
→ RESOLVED

For referral:

READY_FOR_DOCTOR
→ REFERRED
→ UNDER_REVIEW
→ RESOLVED

Keep the state system simple.

==================================================
AI COST CONTROL
==================================================

AI/LLM API calls are paid, so minimize unnecessary AI requests.

Rules:

- Do not call AI endpoints on page loads, refreshes, navigation, or normal
  CRUD operations unless AI is actually required.
- AI should be triggered only by an explicit user action or when the backend
  genuinely needs AI processing.
- Never regenerate an AI summary if a valid summary already exists.
- Store generated AI results in the database and reuse them.
- Do not send the same request/conversation to the AI multiple times.
- Do not use unnecessary polling for AI endpoints.
- Prevent duplicate AI requests caused by React re-renders, component
  mounting, or duplicated event handlers.
- Keep AI conversation context reasonably small; do not send the entire
  history when it is unnecessary.

Examples:

Opening a profile → regular API/DB → NO AI
Opening an existing Patient Case → stored data → NO AI
Viewing an existing AI summary → stored summary → NO AI
Patient sends a new AI message → AI request
Creating/updating a case with AI → AI request
Doctor explicitly requests new AI analysis → AI request

Design the system to be cost-efficient, especially for the hackathon/demo.
