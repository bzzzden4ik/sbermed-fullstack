# SberMedAI / SIRIUS

> AI-платформа для пациентов, врачей и администраторов медицинской организации.

**SberMedAI** — full-stack проект медицинской информационной системы, разработанный в рамках хакатона. Платформа объединяет веб-приложение для пациентов и сотрудников клиники, backend API, ролевую модель доступа, работу с медицинскими данными, AI-ассистентов и MCP-интеграцию.

Основная идея проекта — **создать единый цифровой интерфейс между пациентом и медицинской организацией**, автоматизируя рутинные процессы и помогая пользователю взаимодействовать с клиникой.

При этом AI-ассистент не заменяет врача и не принимает медицинские решения.

---

## 🚀 Возможности

### 👤 Пациент

Пациент может:

* зарегистрироваться и авторизоваться;
* заполнить профиль;
* пройти onboarding;
* ознакомиться с юридическими документами и дать необходимые согласия;
* просматривать список врачей;
* записываться на приём;
* управлять своими записями;
* просматривать медицинские записи;
* получать уведомления;
* использовать AI-ассистента;
* описать проблему или жалобу с помощью AI;
* создавать обращения к врачу;
* просматривать историю обращений;
* продолжать диалог по существующему обращению.

### AI-ассистент пациента

Ассистент помогает пациенту структурировать жалобу:

```text
Пациент
   ↓
Описание проблемы
   ↓
AI собирает дополнительную информацию
   ↓
Формирование структурированного обращения
   ↓
Пациент проверяет информацию
   ↓
Явное подтверждение
   ↓
Обращение передаётся врачу
```

Обращение **не отправляется врачу автоматически** — пациент должен подтвердить сформированную информацию.

AI также не ставит диагноз и не назначает лечение.

---

# 👨‍⚕️ Врач

Для врача доступны:

* личный кабинет;
* список обращений пациентов;
* просмотр подробностей обращения;
* работа с записями на приём;
* работа с пациентами;
* создание назначений;
* AI-ассистент врача;
* просмотр связанной информации по обращениям;
* помощь AI при подготовке ответа пациенту.

AI выступает в роли помощника врача и не заменяет его медицинское решение.

---

# 🧑‍💼 Администратор

Администратор получает доступ к операционной части системы:

* управление врачами;
* управление пациентами;
* просмотр записей на приём;
* статистика обращений;
* статистика приёмов;
* загрузка врачей;
* аналитика клиники;
* AI-ассистент администратора.

AI-ассистент администратора работает в режиме **только чтения** и предназначен для получения и анализа операционной информации.

# 📅 Записи на приём

Backend содержит проверку пересечения записей врача.

При создании или переносе записи система проверяет, занят ли врач в выбранное время.

Отменённые и пропущенные приёмы не блокируют временной слот.

Изменения записей также могут фиксироваться в журнале аудита.

### Жизненный цикл записи

```text
Scheduled
    │
    ├──► Confirmed
    │       │
    │       └──► Completed
    │
    └──► Cancelled

Scheduled / Confirmed
    └──► No Show
```

После создания врачом назначения запись может автоматически переходить в статус `Completed`.

# 🩺 Обращения пациентов

Обращение пациента связано с диалогом AI-ассистента.

Типовой сценарий:

```text
Пациент начинает диалог
          │
          ▼
AI собирает информацию
          │
          ▼
AI структурирует жалобу
          │
          ▼
Пациент проверяет результат
          │
          ▼
Подтверждение
          │
          ▼
Создание обращения
          │
          ▼
Врач получает обращение
          │
          ▼
Врач принимает медицинское решение
```

AI не должен:

* ставить диагноз;
* самостоятельно назначать лечение;
* выдавать медицинское решение от имени врача.

При потенциально критических симптомах ассистент должен рекомендовать обратиться за экстренной медицинской помощью.

# 🧩 Основные принципы проекта

## AI не заменяет врача

Архитектура проекта предполагает разделение ответственности:

```text
AI
 │
 ├── собирает информацию
 ├── структурирует информацию
 ├── ищет информацию в базе знаний
 ├── помогает с операционными задачами
 └── автоматизирует рутинные действия

Врач
 │
 └── принимает медицинское решение
```

---

## Явное подтверждение пациента

Перед отправкой обращения врачу пациент видит собранную AI информацию и должен подтвердить её.

Это снижает риск отправки врачу некорректно интерпретированной информации.

---

## Разделение ролей

Каждый AI-агент имеет собственный набор инструментов:

```text
Patient Agent
    ↓
только patient tools

Doctor Agent
    ↓
только doctor tools

Admin Agent
    ↓
только admin tools
```

---

## AI не обходит авторизацию

MCP-запросы выполняются с учётом JWT пользователя.

Поэтому наличие AI-ассистента не означает наличие доступа ко всей базе данных.

Вызов инструмента проходит через стандартную систему авторизации и проверки принадлежности данных пользователю.

# 🏆 Идея проекта

**SberMedAI / SIRIUS** — это попытка сделать взаимодействие пациента с медицинской организацией максимально простым.

Вместо того чтобы пациенту самостоятельно разбираться:

* к какому врачу обратиться;
* как описать проблему;
* где найти информацию о клинике;
* как записаться;
* где посмотреть результаты предыдущих обращений;

он получает единый цифровой интерфейс.

В результате получается единый workflow:

```text
Пациент
   ↓
AI-ассистент
   ↓
Сбор и структурирование информации
   ↓
Обращение в клинику
   ↓
Врач
   ↓
Медицинское решение
   ↓
Пациент
```
